## 本轮补充

- 组件新增和边界回报同时保存时，后一份旧状态可能覆盖前一份更新。现按顺序处理工作区更新，每次使用最新已保存状态；保存失败不会阻断下一项更新。
- 几何与混合来源交互改用真实鼠标输入，并换算运行页相对主页面的坐标。启动中途失败时也清理该次进程。
- 每个发布清单增加 `SHA-256`（资源摘要算法）完整性信息，记录最终脚本、样式、运行页和协议的实际摘要；连续构建检查同步核对这些值。这是产物核对信息，不代表已建设远程签名发布或加载时强制验签。
- 工作区回归检查先编译再加载最终模块路径；说明文档同步删除“关闭浏览器沙箱”的旧描述。

## 如何复验

先运行 `pnpm run typecheck`（类型检查），再运行 `pnpm run verify:canvas-e2e`（构建并执行真实画板验收）。需要本机有 `trash`（可恢复删除工具）。

专项入口为 `pnpm run test:static-components`（静态产物与来源）、`pnpm run test:workspace-store`（工作区保存）、`pnpm run verify:electron-security`（桌面安全）、`pnpm run verify:bar-position`（工具条恢复）。桌面专项使用前一步生产构建。

如需截图，设置 `DOCKYARD_EVIDENCE_DIR`（证据保存目录）后运行画板验收；失败时该目录也保存现场画面与临时项目状态。
