# 组件视觉资产与本地索引研究

## 结论

1. `shadcn/ui`（组件库）官方仓库与注册表主要分发代码，不是现成的 `PNG`（位图）或 `SVG`（矢量图）素材库。官方注册表的标准条目包含名称、标题、说明、类型、分类、依赖和文件等；没有规定必须提供预览图片。
2. 最接近“可直接用于画稿的组件资源库”的现成方案，是 `shadcn/ui`（组件库）官方文档列出的社区 `Figma`（设计工具）组件库。它们是可编辑的设计组件，不是 `shadcn/ui`（组件库）官方维护的图片包。`Figma API`（设计接口）可以把组件节点批量导出成 `PNG`（位图）、`SVG`（矢量图）、`JPG`（位图）或 `PDF`（文档）。
3. `Storybook`（组件预览工具）是组件运行与展示容器，不是图片资源库。它可以构建为静态网站、通过 `index.json`（故事索引）列出组件状态，再用浏览器截图生成图片；这仍要求某处已经有可运行的组件环境。
4. 对 `Dockyard`（应用）而言，检索匹配不需要图片。应先缓存轻量的 `shadcn/ui`（组件库）注册表目录；图片只作为展示层的可选缩略图缓存，不能作为索引的基础数据。

## 可采用的视觉资产来源

### 1. `shadcn/ui`（组件库）官方注册表

官方把注册表定义为“代码分发系统”，用于分发组件、页面、配置和其他文件。官方程序接口可以直接取得注册表目录，并对名称、标题、类型和说明做模糊检索。

它适合提供：

- 组件身份与名称；
- 标题、说明、类型和分类；
- 安装地址；
- 依赖、注册表依赖与源文件信息。

它不直接提供：

- 每个组件的标准 `PNG`（位图）预览；
- 每个组件的标准 `SVG`（矢量图）预览；
- 统一的视觉状态或尺寸。

依据：

- [注册表介绍](https://ui.shadcn.com/docs/registry)
- [注册表程序接口](https://ui.shadcn.com/docs/registry/api-reference)
- [注册表条目规范](https://ui.shadcn.com/docs/registry/registry-item-json)
- [官方源代码仓库](https://github.com/shadcn-ui/ui)

### 2. 官方文档收录的 `Figma`（设计工具）组件库

`shadcn/ui`（组件库）官方文档有单独的 `Figma`（设计工具）页面，列出免费和付费组件库，并说明这些文件由社区贡献、问题由各文件维护者处理。因此它们是官方认可入口，但不是官方维护资产。

这些资源更接近画稿需求：组件已经重建为设计节点，具有可编辑属性、排版、图标和变体。若能取得文件访问权限，可以通过 `Figma API`（设计接口）读取组件节点，并导出：

- `PNG`（位图）：最适合作为画板缩略图或直接拖入；
- `SVG`（矢量图）：适合需要清晰缩放的静态组件；
- `PDF`（文档）或 `JPG`（位图）：通常不作为画板组件的首选。

限制：

- 需遵守具体社区文件的许可与访问条件；
- 不同社区套件与当前代码版本可能存在偏差；
- 弹出层、提示框等交互组件要预先定义“展开状态”，单个组件不只有一张图；
- `Figma API`（设计接口）的图片链接会过期，因此 `Dockyard`（应用）若使用它，应下载后形成自己的缓存，而不是长期保存临时链接。

依据：

- [`shadcn/ui`（组件库）的 `Figma`（设计工具）资源页](https://ui.shadcn.com/docs/figma)
- [免费组件库一：`shadcn/ui components`（组件设计文件）](https://www.figma.com/community/file/1342715840824755935)
- [免费组件库二：`shadcn/ui design system`（组件设计系统）](https://www.figma.com/community/file/1203061493325953101)
- [免费组件库三：`Obra shadcn/ui Community Edition`（社区版组件库）](https://www.figma.com/community/file/1514746685758799870/)
- [`Figma REST API`（设计文件接口）的节点与图片导出](https://developers.figma.com/docs/rest-api/file-endpoints/)
- [`Figma Plugin API`（设计插件接口）的节点导出能力](https://developers.figma.com/docs/plugins/api/properties/nodes-exportasync/)

### 3. `Storybook`（组件预览工具）与浏览器截图

`Storybook`（组件预览工具）可以把每个组件状态定义为一个 `story`（组件故事），构建为静态网站；`index.json`（故事索引）可列出故事标识、标题、标签等元数据。`Storybook`（组件预览工具）的官方视觉测试会把每个故事转成像素快照，但默认通过 `Chromatic`（云端视觉测试服务）完成，并不是一个公开图片素材下载库。

如果组件库本身已有公开的 `Storybook`（组件预览工具），`Dockyard`（应用）可以：

1. 读取其 `index.json`（故事索引）；
2. 打开指定故事的独立预览页；
3. 用 `Playwright`（浏览器自动化工具）只截取组件节点；
4. 缓存得到的 `PNG`（位图）。

这比为每个候选单独安装依赖好，但前提是目标组件库已经发布了可访问的预览站。它不能解决“只有注册表源代码、没有运行环境”的情况。

依据：

- [`Storybook`（组件预览工具）静态发布](https://storybook.js.org/docs/sharing/publish-storybook)
- [`Storybook`（组件预览工具）视觉测试](https://storybook.js.org/docs/writing-tests/visual-testing)
- [`Storybook`（组件预览工具）的 `index.json`（故事索引）命令](https://storybook.js.org/docs/api/cli-options)
- [`Playwright`（浏览器自动化工具）元素截图](https://playwright.dev/docs/screenshots)

## `Dockyard`（应用）本地组件索引应缓存什么

若当前只针对 `shadcn/ui`（组件库），建议把缓存拆成三层。

### 第一层：检索目录，必须缓存

每个条目保存：

- `registry`（注册表命名空间）与组件唯一标识；
- `name`（名称）、`title`（标题）、`description`（说明）；
- `type`（类型）、`categories`（分类）；
- `addCommandArgument`（安装地址参数）；
- 来源地址、抓取时间、来源版本或内容摘要；
- `Dockyard`（应用）补充的中英文别名、同义词和用途标签。

这一层体积很小，可定期刷新，并直接用于草图识别结果的本地排序。官方接口已经提供 `searchRegistries`（搜索注册表）能力，返回的目录结果本身不含文件内容，很适合做本地索引。

### 第二层：候选详情，按需缓存

仅在候选进入前几名或用户查看详情时保存：

- `dependencies`（包依赖）；
- `registryDependencies`（注册表依赖）；
- `files`（源文件清单，必要时含内容）；
- `cssVars`（样式变量）、`css`（样式规则）；
- `docs`（安装说明）、`meta`（扩展信息）。

这层用于判断组件能否直接采用、将来如何安装，不应在每次普通检索时全部下载。

### 第三层：视觉缩略图，可选缓存

图片不参与基础匹配，只用于让用户快速确认外观。建议保存：

- 一张默认明亮主题 `PNG`（位图）缩略图；
- 可选的一张暗色主题缩略图；
- 对浮层类组件增加一张“打开状态”缩略图；
- 图片对应的组件版本、主题和状态标识。

不建议为每次查询即时安装和渲染。缩略图可以来自：

1. 已获许可的 `Figma`（设计工具）组件库批量导出；
2. `Dockyard`（应用）维护者离线统一渲染后随组件目录发布；
3. 已公开的 `Storybook`（组件预览工具）页面按需截图。

## 对当前流程的建议

推荐默认路径：

```text
草图 → 一次模型识别 → 本地目录匹配 → 直接展示预置缩略图 → 用户确认候选
```

此路径不需要在用户项目中安装依赖。只有用户最终选择“采用代码组件”时，才检查目标项目已有依赖并展示将要增加的内容；安装必须是单独、明确的操作。

视觉资产优先使用 `PNG`（位图）放入画板，因为显示稳定、无需字体和运行时；同时保留组件唯一标识和来源信息，保证“画稿中的图片”仍能关联回真实代码组件。`SVG`（矢量图）可作为补充，但复杂组件的字体、滤镜和外部资源更容易出现兼容差异。
